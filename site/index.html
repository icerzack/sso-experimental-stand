5. Mitigation and Best Practices

  • A1 Brute Force: repeated password guessing against one account. Mitigation: per-user and per-IP rate limits, temporary lockout, progressive delays, and monitoring for repeated failures.
  • A2 Credential Stuffing: reuse of leaked credentials at scale. Mitigation: bot detection, breached-password checks, MFA/passkeys, anomaly detection, and anti-automation controls.
  • A3 Phishing (WebAuthn): attacker tries to authenticate from a fake origin. Mitigation: enforce WebAuthn origin and RP ID validation, require user verification, and keep origin policy strict.
  • A4 Token Replay: reuse of an old token/session after logout. Mitigation: server-side session invalidation, token revocation lists, short token TTL, and rotating refresh/access tokens.
  • A5 JWT alg:none: algorithm downgrade to bypass signature checks. Mitigation: explicit algorithm allowlist, strict issuer/audience checks, key rotation, and reject unsigned tokens.
  • A6 Session Hijacking: stolen cookie reused by attacker. Mitigation: HttpOnly, Secure, SameSite, session rotation on login, and optional device/IP binding.
  • A7 redirect_uri abuse: redirecting OAuth flow to attacker-controlled endpoint. Mitigation: exact redirect URI matching, no wildcard/substr checks, strict allowlist only.
  • A8 CSRF/state bypass: forged authorization callback or missing state/PKCE checks. Mitigation: mandatory one-time state, nonce validation, PKCE (S256) required, and callback strictness.
  • A10 IdP SPOF: auth unavailable if IdP is down. Mitigation: HA IdP deployment, replication, health probes, automated failover, and clear degraded-mode behavior.
  • A11 DB Leak: exposed secrets/credentials in dumps or storage. Mitigation: secrets manager, encryption at rest, least-privilege DB access, secret scanning, and sanitized logs/backups.
  • A12 Security Headers: missing browser-side hardening protections. Mitigation: enforce HSTS, CSP, X-Frame-Options (or CSP frame-ancestors), X-Content-Type-Options, and Referrer-Policy.
